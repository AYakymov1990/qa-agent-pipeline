# Тестові дані під чек-лист

Мета — щоб у агента не лишилось жодного питання «з чим перевіряти». Дані, які знадобляться в інших задачах, живуть у довіднику; тут — тільки зіставлення.

## Джерела (у порядку пріоритету)

1. **Довідник тестових даних** — `$CODEWIKI_PATH/kb/QA/test-data.md`: записи з ID `TD-…` (площадка, роль, обʼєкт, стенд, змінна `.env` для акаунта, дата перевірки).
2. **Рецепти** — `$CODEWIKI_PATH/kb/QA/howto/*.md`: як отримати стан (геолокація за IP, неоплачене замовлення, збережена адреса…), позначка «Агенту можна: так / ні».
3. **Дані задачі** — `tasks/<ID>/data.md`: те, що QA дав саме під цю задачу (стенд, особливий продавець). Шаблон — `templates/data.md`.

Немає `$CODEWIKI_PATH` або розділу `kb/QA/` — скажи про це (QA-режим) або запиши в звіт (dev-режим) і працюй тільки з `data.md`.

## Що зробити

Для кожного рядка «агент» (у dev-режимі — тільки P1/P2 без допущень):

1. Розбери «Данные:» на складові: площадка, роль (гість / покупець / продавець), тип продавця і доставки, товар, адреса, IP, стан (сохранённый адрес, заказ…).
2. Для кожної складової знайди TD-запис або рецепт. Акаунт — тільки змінна з `.env` і тільки тестовий користувач (`StaticUserHelper.TestUsers`); перевір, що змінна є в `.env.example`.
3. Рецепт з «Агенту можна: ні» — передумова для QA (`needs_qa`).
4. Запиши рішення:
    ```bash
    .venv/bin/python scripts/checklist.py set --task <ID> CHK-001 CHK-002 data_refs=TD-003,TD-011,howto/geo-ip data_status=ok
    .venv/bin/python scripts/checklist.py set --task <ID> CHK-045 data_status=missing
    ```
5. `tasks/<ID>/data.md` — таблиця «CHK → дані» і список того, чого бракує, з конкретним питанням: «Потрібен mapped-дропшиппер на es.seller2 з дозволеними ES/PT/FR — є такий у довіднику?».

## Режими

- **QA**: бракує даних — одним списком питань QA. Відповіді — у `data.md` і, якщо знадобиться в інших задачах, у блок «Зберегти в контекст?» (`qa-context-update`). Після відповіді — `data_status=ok`.
- **Dev** (`--auto --state <run>`): без питань; виклики `checklist.py` — з `--state <run>`, зіставлення — у `<run>/data.md`. Не знайшов — `data_status=missing`; рядок не піде в прогін, у звіті — «немає тестових даних: <що саме>».

## Правила

- Не вигадуй даних і не бери «схожий» запис з іншої площадки чи стенду.
- Запис довідника з датою перевірки старше 30 днів — `data_status=ok`, але позначка «перевірить розвідка / перший кейс».
- Паролі — тільки в `.env`; у `data.md` — назви змінних.
