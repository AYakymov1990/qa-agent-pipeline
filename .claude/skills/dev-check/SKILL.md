# Dev-режим: /dev-check <ID> [стенд] [площадка]

Для розробника перед переведенням задачі в тест. **Без запитань і пауз**: усе, що потребує рішення людини, не береться в прогін і потрапляє в звіт як «не перевірено агентом — причина». Ціль — швидко і надійно спіймати поломку основного функціоналу, а не повне тестування.

Стенд і площадка — з аргументів, інакше `TEST_STAND` / `TEST_SITE` з `.env`. Немає — зупинись з повідомленням (це єдиний випадок, коли dev-режим зупиняється до старту).

## Порядок

Папка прогону: `tasks/<ID>/runs/<YYYYMMDD-HHMM>-dev-<QA_USER>/` (далі `<run>`).

**Dev-прогін пише тільки у свою папку `<run>/`** — спільні файли задачі (`checklist.json`, `data.md`, `spec/`, `pipeline.md`) належать QA-режиму і не змінюються. Тому всі виклики `scripts/checklist.py` — з `--state <run>`, журнал кроків — `<run>/log.md`. Класифікацію і дані, які QA вже підтвердив у `tasks/<ID>/checklist.json`, імпорт бере як основу автоматично.

1. **Вхід** — `qa-ado-fetch <ID>` (якщо `input/` є — тільки перевірка ревізії і нових коментарів). Немає вкладеного чек-листа — вердикт «⚠️ Не перевірено: у PBI немає чек-листа», кінець.
2. **Імпорт** — `qa-checklist-import <ID> --auto --state <run>`: класифікація без запитань; рядки, підтверджені QA (`confirmed`), не змінюються.
3. **Маршрут** — за правилами `qa-test` § 2, без питань; від маршруту — ліміт перевірок (`routes.<S|M|L>.dev_max_cases`).
4. **Дані** — `qa-test-data <ID> --auto --state <run>`: рядок без підтверджених даних (`data_status` ≠ ok) у dev-прогін не йде; зіставлення — у `<run>/data.md`.
5. **Відбір**:
    ```bash
    .venv/bin/python scripts/checklist.py select --task <ID> --state <run> --mode dev --run <run> --max <ліміт маршруту>
    ```
    Правила dev-відбору (`pipeline.config.json` → `selection.dev`): тільки «агент»; P1, потім P2 (P3 — граничні випадки — ні); без допущень `Q-xx`; без передумов, які готує QA; без регресу; тільки з даними. Порядок — P1 першими.
    Взято 0 — вердикт «⚠️ Не перевірено агентом» з причинами з `selection.md`, кінець.
6. **Кейси** — для кожної відібраної перевірки:
    - є QA-кейс зі статусом «готовий» або «стабільний» у `tasks/<ID>/spec/cases/`, що покриває цей CHK, — **бери його** (він уже вивірений QA);
    - немає — `qa-agent-spec <ID> --mode dev --run <run>`: кейси в `<run>/cases/`, коротко, без окремої специфікації.
7. **Прогін** — `qa-agent-run <ID> --mode dev --run <run>`: автоматичний режим, без пауз, порядок — P1 першими.
    - **P1 FAIL** (і `dev_check.stop_on_p1_fail`) — далі P1, але P2 уже не запускай: вердикт однозначний, час розробника дорожчий.
    - Ліміт часу — `dev_check.time_budget_minutes`; вичерпано — решта «не запущено», вердикт за тим, що встигли.
    - Стоп-умови (капча, 429 / 423, чужий хост, бойовий контур) — прогін зупиняється, вердикт «⚠️ Перевірку перервано: <причина>».
8. **Результати** — `checklist.py fill --task <ID> --state <run> --run <run>` (копія чек-листа з «Прогон N» у `<run>/`), `report.md`, `report.html`, метрики.
9. **Вердикт** — перший рядок звіту після шапки: `**Вердикт:** …`:
    - **✅ Готово до тесту** — усі запущені P1 і P2 PASS (FLAKY — не PASS: ✅ тільки якщо FLAKY немає серед P1);
    - **❌ Не готово** — хоч один FAIL; перелік — CHK, очікувалось, фактично, скріншот;
    - **⚠️ Не перевірено повністю** — BLOCKED серед P1 або прогін перервано.
    Під вердиктом — «Що не перевірено агентом» з `selection.md` (вручну / допущення / дані) — щоб розробник бачив межі перевірки.
10. **Коміт** — `scripts/dev-check.sh` комітить `<run>/` сам; з інтерфейсу Claude Code — запропонуй `scripts/commit-run.sh <ID>`.

## Чого dev-режим не робить

- Не питає і не чекає відповіді. Сумнів у вердикті — FAIL з позначкою «потребує рішення QA», вердикт ❌ з поясненням.
- Не пише баг-репорти, не змінює класифікацію, підтверджену QA, не правлять автотести.
- Не пропонує блок «Зберегти в контекст?» — кандидати тільки дописує в `tasks/<ID>/context-candidates.md` для QA.
- Не змінює нічого в Azure DevOps (як і весь pipeline).

## Підсумок

У чаті / в stdout — 3–5 рядків: вердикт, PASS / FAIL / BLOCKED, що не перевірено агентом, шлях до `report.html`.
