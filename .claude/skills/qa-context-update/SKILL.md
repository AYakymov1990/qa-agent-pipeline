# Поповнення контексту

Мета — щоб дані й знання з однієї задачі працювали в наступних. Записує **тільки з підтвердження** («так», «так 1, 3», «запамʼятай …» — це вже підтвердження).

## Де живе контекст

- Читання: `context-outbox/kb/QA/` (ще не перенесені правки), потім `$CODEWIKI_PATH/kb/QA/`.
- Запис: **тільки** `context-outbox/` — нова версія файла за тим самим шляхом (`context-outbox/kb/QA/test-data.md`) + рядок у `context-outbox/CHANGES.md`. CodeWiki не змінюється (`context-outbox/README.md`).

| Що | Файл у `kb/QA/` |
| --- | --- |
| Тестові дані — акаунти (назви змінних `.env`), продавці, товари, адреси, стан прапорців на стендах | `test-data.md`, запис з новим ID `TD-xxx` |
| Як отримати стан / пройти службовий сценарій | `howto/<тема>.md` за шаблоном `qa-context-intake/templates/howto.md` + рядок у `howto/README.md` |
| Терміни, синоніми, назви в UI за площадками | `glossary.md` |
| Площадки, ролі, оточення, severity / priority | `PROJECT.md` |
| Карта автотестів | `autotests-map.md` |

## Звідки кандидати

- Блок «Зберегти в контекст?» від інших скілів; dev-режим лише дописує кандидатів у `tasks/<ID>/context-candidates.md` — покажи їх QA при наступному `/qa-test <ID>`.
- Факт від QA в чаті — покажи блок, навіть якщо не просив.

Не зберігай: стан, корисний лише для цієї задачі; паролі, токени, персональні дані (паролі — тільки `.env`); здогадки без джерела.

## Формат блоку

```text
Зберегти в контекст?
1. [test-data.md] TD-новий: es · mapped-дропшиппер «…», дозволені ES/PT/FR (seller2, перевірено YYYY-MM-DD)
2. [glossary.md · Назви в UI] es: «Direcciones guardadas» — Збережені адреси
3. [howto/geo-ip.md] перевірено на seller2, YYYY-MM-DD — агенту можна: так
Відповідайте: «так», «так 1, 3» або «ні».
```

Показавши блок — збережи пункти в `tasks/<ID>/context-candidates.md`; після відповіді — прибери оброблені.

## Як записувати

1. Візьми актуальну версію файла (outbox, інакше CodeWiki), збережи структуру розділів і таблиць.
2. Дубль — не дублюй, онови «Перевірено». Конфлікт — покажи «було / стало», запиши тільки після відповіді.
3. Біля кожного факту — джерело: `[зі слів QA, YYYY-MM-DD]`, `[задача <ID>, прогін <…>]`.
4. Тестові дані — завжди стенд і дата перевірки. Не спрацювали на стенді — запропонуй позначку «не актуально на sellerN, YYYY-MM-DD».
5. Рядок у `context-outbox/CHANGES.md`; скажи одним рядком, що і куди, і нагадай: перенесення в CodeWiki — `docs/codewiki-qa-section.md`.
