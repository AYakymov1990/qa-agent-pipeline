# Оновлення автотестів під зміну

Мета — щоб після релізу задачі регрес не падав «очікувано», а автотести вже перевіряли нову поведінку.

## Вхід

- `tasks/<ID>/autotests-coverage.md` → «Тести, які потребують оновлення» (немає файла — спершу `qa-autotests-coverage`).
- Очікувана нова поведінка — **тільки з чек-листа** (`checklist.json`, CHK) і задачі; код гілки показує, *що* змінилось, але не є еталоном.
- Проєкт автотестів — `$AUTOMATION_PATH`.

## Стандарти проєкту автотестів — головні

Перед будь-якою правкою прочитай у `$AUTOMATION_PATH`: `CLAUDE.md`, `.claude/skills/*`, `README`, правила code style, структуру page objects / компонентів, як іменуються тести і категорії. Якщо в проєкті є власний скіл для написання чи правки тестів — **використовуй його** (`Skill` або його інструкції), а не правила цього репозиторію. Конфлікт правил — правила проєкту автотестів.

## Порядок

1. **Гілка в окремій робочій копії** — основна копія QA не змінюється (спершу `git -C "$AUTOMATION_PATH" fetch origin`):
    ```bash
    git -C "$AUTOMATION_PATH" worktree add "../AvtoProAutomation-<ID>" -b autotests/<ID> origin/<основна гілка>
    ```
    Основну гілку — з карти автотестів або `git -C "$AUTOMATION_PATH" symbolic-ref refs/remotes/origin/HEAD`. Гілка вже є — продовжуй у ній.
2. **План** — QA бачить перелік: тест, що змінюється, чому (CHK / зміна в гілці), як. Чекай «так».
3. **Правки** — мінімальні: оновити очікування, локатор, крок. Нових тестів — тільки якщо QA попросив. Не вимикай і не пропускай тести (`[Ignore]`, `skip`) замість правки.
4. **Прогін** — тільки змінені тести, на тестовому стенді з гілкою розробника (хост — за `stands.host_pattern`), командою з карти / README. Конфіг стенду і секрети — з локальних налаштувань проєкту автотестів, нічого не комітити з секретами.
5. **Коміт** у гілці `autotests/<ID>` за правилами комітів проєкту автотестів; повідомлення з номером задачі.
6. **Push і PR — людина.** Дай QA готові команди і опис PR: які тести, чому, посилання на PBI, результат прогону; позначка «злити разом з релізом задачі <ID>».
7. Рядок у `tasks/<ID>/pipeline.md` і в `autotests-coverage.md` («оновлено в гілці autotests/<ID>»).

## Правила

- Код AvtoPro — тільки читання.
- Не змінюй основну робочу копію `$AUTOMATION_PATH` і не пуш.
- Після злиття PR — запропонуй прибрати worktree: `git -C "$AUTOMATION_PATH" worktree remove ../AvtoProAutomation-<ID>`.
