# Прогін агентом

## Перед стартом — обовʼязково

Будь-яка не пройдена — **зупинись** (QA-режим — скажи QA; dev-режим — вердикт «⚠️ Не перевірено: <причина>»).

1. Є кейси: QA-режим — `tasks/<ID>/spec/cases/_index.md` зі статусом «готовий» / «стабільний» («чернетка» — тільки з дозволу QA); dev-режим — `<run>/cases/_index.md`.
2. **Захист від проду.** Хост стенду відповідає `stands.host_pattern` з `pipeline.config.json` (`^(avto|es|pt|pl|tr|ua)\.seller[1-5]\.vus\.us$`). Інший хост, зокрема avto.pro, avtopro.*, — не відкривай. Перевіряй хост перед **кожною** дією.
3. Акаунти кейсів — змінні з `.env`, і кожна є в `.env.example`. Паролі — тільки для входу, **ніколи** у звіти, кейси, чат, коміти.
4. Інструменти Playwright MCP є в сесії. Немає — `.mcp.json` і перезапуск Claude Code.

## Режими

| Режим | Як | Коли |
| --- | --- | --- |
| **Покроковий** (QA за замовчуванням) | Після кожного кейсу — картка і пауза до відповіді QA | Калібрування, маршрути M і L |
| **Детальний** | Пауза й після кожного кроку | Перший кейс задачі L або на прохання QA |
| **Автоматичний** | Без пауз, звіт наприкінці | Маршрут S, QA довіряє вердиктам; **завжди в dev-режимі** |

QA змінює режим словами «детально», «покроково», «автоматично» в будь-який момент. У dev-режимі пауз немає взагалі.

### Картка кейсу (покроковий режим)

```text
TC-003 — <мета> · P1 · FAIL (спроба 2 з 2)
Що зробив: 1. …  2. …  3. …
Перевірки:
  ✅ CHK-012 — очікувалось «…», факт «…»
  ❌ CHK-013 — очікувалось «…», факт «…» · скрін TC-003/step-4.png
Висновок агента: дефект продукту / дефект кейсу / проблема оточення / потребує рішення QA
Далі: «так» · «повтори» · «вердикт: <ваш вердикт і чому>» · «стоп»
```

Незгода QA («вердикт: …») — результат = вердикт QA з позначкою «змінено QA» і рядок у `<run>/calibration.md` (кейс, CHK, агент, QA, причина). Наприкінці — частка згоди і пропозиції правок кейсів чи правил оцінки (застосовуються з підтвердження QA).

## Прогін

Папка `<run>` = `tasks/<ID>/runs/<YYYYMMDD-HHMM>-<qa|dev>-<QA_USER>/` (dev — уже створена `/dev-check`).

1. Одразу — `<run>/report.md` за `templates/run-report.md` з усіма кейсами «не запущено» і `<run>/results.json` = `{}`. Позначка `metrics.py mark --run <run> --tc RUN --event start`.
    - QA-режим, є незавершений прогін (кейси «не запущено») — спитай: продовжити його чи новий.
2. **Доступ до стенду**: сторінка пароля закритої площадки — `TEST_ENV_PASSWORD` (cookie `TestEnvAccessToken`, 7 днів).
3. Для кожного кейсу в порядку `_index.md` (P1 першими):
    - `metrics.py mark --run <run> --tc TC-xxx --event start`;
    - чистий стан: потрібний акаунт (імʼя в шапці), потрібний хост, cookie `showTestUsers`, якщо треба; `platform: mobile-web` — вікно 390×844;
    - передумова з рецептом «Агенту можна: так» — виконай; «ні» — переконайся, що стан є, інакше BLOCKED «передумову готує QA»;
    - кроки — за знімком доступності сторінки; для кожного пункту очікуваного зафіксуй **факт**: дослівний текст / число, URL, запит у Network (метод, статус, поле), помилки Console;
    - таблиця варіантів — кожен варіант окремо;
    - скріншот — на кожному FAIL і BLOCKED і на ключовому кроці → `<run>/TC-xxx/`;
    - «Очищення» кейсу;
    - **одразу**: рядок кейсу і рядки CHK у `report.md`; кожен CHK — у `results.json`: `{"CHK-012": {"status": "PASS|FAIL|BLOCKED|FLAKY", "tc": "TC-003", "note": "факт коротко"}}`;
    - `metrics.py mark … --event end [--note "що забрало час"]`;
    - покроковий режим — картка і пауза; відповідь QA — у колонку «Апрув QA».
4. **Результат пункту:**
    - **PASS** — факт збігається з очікуваним дослівно (тексти) або точно (числа);
    - **FAIL** — не збігається; повтори кейс один раз з чистого стану: знову FAIL → FAIL; тепер PASS → **FLAKY**;
    - **BLOCKED** — крок неможливий (елемента немає, немає даних, оточення), очікування понад 15 хв;
    - неоднозначний факт або рядок з допущенням `Q-xx`, де факт ≠ допущенню, — **FAIL «потребує рішення QA»**, не PASS.
5. **Dev-режим додатково**: P1 FAIL і `dev_check.stop_on_p1_fail` — дограй P1, P2 не запускай (у звіті — «не запущено: P1 FAIL»); вичерпано `dev_check.time_budget_minutes` — решта «не запущено».
6. **Зупинка всього прогону**: капча, 429 / 423, перенаправлення на хост поза стендом, ознаки бойового контуру (сторінка реального банку, лист реальному клієнту) — збережи доказ, зупинись, повідом (dev — вердикт ⚠️).

## Після прогону

1. **Звіт** — підсумок і «Деталі FAIL, BLOCKED, FLAKY»; dev-режим — рядок `**Вердикт:** ✅ Готово до тесту / ❌ Не готово / ⚠️ Не перевірено повністю` (правила — `dev-check` § 9) і розділ «Не взято в прогін» з `selection.md`.
2. **Чек-лист** — копія оригіналу з результатами в першій вільній колонці «Прогон N» (статуси: PASS → «Успешно», FAIL → «Баг», BLOCKED / FLAKY → «Пропущено»; пояснення — у примітці комірки):
    ```bash
    .venv/bin/python scripts/checklist.py fill --task <ID> --run <run>             # QA-режим
    .venv/bin/python scripts/checklist.py fill --task <ID> --run <run> --state <run>  # dev-режим
    ```
    Оригінал у `input/` не змінюється. Файл `<run>/checklist-<run>.xlsx` QA прикріплює до PBI сам.
3. **Кейси** (QA-режим) — статуси в `spec/cases/_index.md`: 3 прогони поспіль з однаковим результатом → «стабільний».
4. **Баги** (QA-режим) — для FAIL без «потребує рішення QA» — чернетки `qa-bug-report` у `tasks/<ID>/bugs/`.
5. **Метрики**:
    ```bash
    .venv/bin/python .claude/skills/qa-agent-run/scripts/metrics.py mark --run <run> --tc RUN --event end
    .venv/bin/python .claude/skills/qa-agent-run/scripts/metrics.py run --run <run> --task <ID>
    .venv/bin/python .claude/skills/qa-agent-run/scripts/metrics.py task --task <ID>
    ```
    У звіті — розділ «Метрики»: 3–5 висновків і «Втрати часу» (причина, хв, як уникнути).
6. **HTML** — `.venv/bin/python .claude/skills/qa-agent-run/scripts/report_html.py <run>` → `<run>/report.html` (один файл; скріншоти — відносними посиланнями).
7. **Контекст** — назви в UI, яких немає в глосарії, і дані, що спрацювали / не спрацювали: QA-режим — блок «Зберегти в контекст?»; dev-режим — тільки дописати в `tasks/<ID>/context-candidates.md`.
8. **Підсумок** — 3–6 рядків: (вердикт), PASS / FAIL / BLOCKED / FLAKY, згода QA з агентом, що потребує рішення QA, чернетки багів, тривалість і вартість, шлях до `report.html`.

## Правила

- Не змінюй кейс під час прогону і не трактуй розбіжність на користь системи.
- Не шукай обхідних шляхів: кнопки немає — це результат.
- Побачив проблему поза кейсом — «Помічено поза чек-листом», не досліджуй.
