# Задача з Azure DevOps

**Тільки читання.** Нічого не створюй і не змінюй в Azure DevOps — інструменти запису заборонені в `.claude/settings.json`.

MCP-сервер `azure-devops` (організація `abp`, проєкт `Avto.Pro`, `.mcp.json`). Немає інструментів `mcp__azure-devops__*` або помилка входу — QA-режим: підкажи `/mcp` і `docs/setup.md` § Azure DevOps; dev-режим: зупинись з цим повідомленням.

## Що отримати

1. **Задача** — `wit_get_work_item` з полями і звʼязками: назва, тип, стан, Area, Iteration, теги, призначено, ревізія (`rev`); опис і критерії приймання — дослівно (HTML → markdown без переказу).
2. **Коментарі** — `wit_list_work_item_comments`: автор, дата, текст.
3. **Звʼязки** — батьківська, дочірні, повʼязані (номер, тип, назва, стан); **Development** — гілки і PR розробника.
4. **Чек-лист** — вкладення (`AttachedFile`) `.xlsx`:
    - кілька xlsx — бери той, у назві якого є номер задачі або «чек-лист» / «check», найновіший за датою; сумнів — QA-режим: спитай; dev-режим: найновіший + позначка в `ado-sync.md`;
    - завантаж в `tasks/<ID>/input/checklist.xlsx`: інструмент MCP для вкладень, якщо він є; інакше — `.venv/bin/python scripts/ado_attachment.py --url "<url вкладення>" --out tasks/<ID>/input/checklist.xlsx` (потрібен `ADO_PAT` у `.env`, права Work Items — Read);
    - не вдалося — QA-режим: попроси QA зберегти файл у `tasks/<ID>/input/checklist.xlsx`; dev-режим: зупинись з повідомленням «у PBI немає доступного чек-листа».

## Куди записати

- `tasks/<ID>/input/task.md` — поля, опис і критерії дослівно, звʼязки, гілка розробника, Figma, вкладення (імена, дати).
- `tasks/<ID>/input/comments.md` — від старих до нових: `### <автор> · YYYY-MM-DD HH:MM` і текст дослівно.
- `tasks/<ID>/input/ado-sync.md` — коли отримано, `rev`, кількість коментарів, ID останнього, імʼя і дата вкладення чек-листа.

`input/` не комітиться — це кеш; будь-хто отримає його заново.

## Повторне отримання

Є `ado-sync.md`:

- нові коментарі — допиши в `comments.md`;
- змінились опис чи критерії — онови `task.md`, у підсумку — що змінилось;
- **новий чек-лист** (інше вкладення або новіша дата) — збережи попередній як `checklist-<дата>.xlsx`, завантаж новий і скажи, що треба повторити `qa-checklist-import` (він збереже класифікацію незмінених рядків).

## Правила

- Опис, критерії і коментарі — дослівно, без скорочень.
- Персональні дані клієнтів (телефони, email) — заміни на `[персональні дані]`.
- Підсумок у чаті — 2–4 рядки: назва, тип, стан; нові коментарі; гілка; чек-лист (імʼя, дата).
