# Розвідка перед прогоном (QA-режим)

Мета — щоб прогін не спотикався: кейси написані під **реальний** інтерфейс стенду, дані й передумови на місці. Розвідка **не тестує** — вердиктів немає. Один раз на задачу або на нову збірку стенду; для «стабільних» кейсів не потрібна. Dev-режим розвідки не робить.

## Перед стартом

Ті самі перевірки, що в `qa-agent-run` § «Перед стартом» (кейси, захист від проду, тестові акаунти, Playwright MCP).

Спитай QA одне: **чи можна створювати дані** (кошик, заповнення форм без фінального підтвердження) — «так» / «ні». За замовчуванням — ні.

## Що робити

1. **За сторінками, а не за кейсами**: кейси, що проходять тими самими сторінками, розвідуй разом.
2. Для кожної сторінки — у `tasks/<ID>/spec/recon.md` за `templates/recon.md`: URL і як потрапити; ключові елементи з кроків — **дослівна видима назва і роль**; стабільні атрибути (`data-testid`, `id`) — знадобляться для автотестів; перешкоди (cookies-банер, модальні вікна, iframe Stripe, довге завантаження, капча); відмінності площадок і мобільної версії (390×844).
3. **Передумови і дані**: вхід під кожним акаунтом працює; продавці, товари, адреси з TD існують на цьому стенді; рецепти howto виконуються; прапорці (за поведінкою сторінки).
4. **Не фіналізуй**: не оформлюй, не оплачуй, не надсилай форм, що створюють дані.
5. **Розбіжності**: крок неможливий так, як написано, або елемент називається інакше — **правка кейсу**; інтерфейс розходиться з чек-листом — **потенційна знахідка** (не вердикт), перевірить прогін.
6. Скріншоти ключових сторінок — `tasks/<ID>/spec/recon-YYYY-MM-DD/`.

## Видача

1. `spec/recon.md`.
2. **Правки кейсів** — список «було → стало» по кожному TC; QA: «так» / «так 1, 3» / «ні». Застосуй тільки підтверджені; статус «чернетка» → «готовий».
3. Дані, що не підтвердились на стенді, — `checklist.py set … data_status=missing` і питання QA; дані, що спрацювали, — дата перевірки в блок «Зберегти в контекст?».
4. У `spec/cases/_index.md` — «Розвідка: YYYY-MM-DD, <стенд>, збірка <…>»; рядок у `pipeline.md`.

## Правила

- Ніяких PASS / FAIL — це робота `qa-agent-run`.
- Капча, 429 / 423, чужий хост, бойовий контур — зупинись і повідом QA.
- Паролі з `.env` — тільки для входу, ніде не записуй.
