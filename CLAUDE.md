# Інструкції для Claude у цьому репозиторії

QA agent pipeline AvtoPro — спільний для QA і розробників. Тут не пишемо продакшн-код: беремо готовий чек-лист задачі з Azure DevOps і перевіряємо реалізацію агентом у браузері.

Аналіз PBI (ревʼю вимог, аналіз гілки, запити в документацію, написання чек-листа) — **окремий процес до цього pipeline**. Сюди приходить уже проаналізований чек-лист без відкритих питань.

## Режими

| Команда | Хто | Що робить |
| --- | --- | --- |
| `/qa-test <ID> [стенд] [площадка]` | QA | Усі проверки, які може агент; кейси переглядає QA; розвідка з апрувом правок; покроковий прогін з апрувом; баг-репорти; правка автотестів |
| `/dev-check <ID> [стенд] [площадка]` | Розробник | Тільки основний функціонал задачі; повністю автоматично; вердикт «Готово до тесту ✅ / Не готово ❌» |

Скрипт-кнопка для розробника без інтерфейсу Claude Code: `scripts/dev-check.sh <ID> [стенд] [площадка]`.

## Потік

1. `qa-ado-fetch` — задача і вкладений чек-лист (xlsx) з Azure DevOps → `tasks/<ID>/input/`.
2. `qa-checklist-import` — розбір чек-листа і класифікація кожної перевірки → `tasks/<ID>/checklist.md` (+ `.json`).
3. Маршрут S / M / L — за типом PBI і мітками.
4. Відбір перевірок під режим; регрес, покритий автотестами, не дублюємо (`qa-autotests-coverage`).
5. `qa-test-data` — дані для кожної відібраної перевірки є в довіднику.
6. `qa-agent-spec` — специфікація кейсів для агента.
7. `qa-agent-recon` (QA) → `qa-agent-run` — розвідка і прогін через Playwright MCP.
8. Результати — у колонку «Прогон N» копії чек-листа, звіт і HTML — у `tasks/<ID>/runs/<прогін>/`, коміт — `scripts/commit-run.sh`.
9. QA: `qa-bug-report`, `qa-autotests-update`.

## Завжди

- Контекст проєкту (PROJECT, глосарій, довідник тестових даних TD-…, рецепти howto, карта автотестів) — у CodeWiki, розділ `kb/QA/` (`$CODEWIKI_PATH`). Читай спершу `context-outbox/kb/QA/` (ще не перенесені правки), потім CodeWiki.
- Чек-лист задачі — джерело правди для очікуваних результатів. Не змінюй формулювань перевірок і не додавай нових; знайдена прогалина — у звіт «Помічено поза чек-листом».
- Артефакти задачі — тільки в `tasks/<ID>/`. Прогони — в окремих папках `runs/<YYYYMMDD-HHMM>-<qa|dev>-<QA_USER>/`.
- **Dev-режим пише тільки у свою папку прогону** (`checklist.py … --state <run>`); спільні файли задачі (`checklist.*`, `data.md`, `spec/`, `pipeline.md`) — тільки QA-режим. Так QA і розробники не конфліктують у git.
- Мова артефактів pipeline — українська; тексти чек-листа й UI — дослівно, як є.
- Налаштування (стенди, формат чек-листа, правила класифікації й відбору, маршрути) — `pipeline.config.json`; машинні шляхи, стенд за замовчуванням і акаунти — `.env`.
- Python — `.venv/bin/python` (немає — `python3`).

## Ніколи

- Паролі, токени, ключі, персональні дані — тільки в `.env`, ніколи у файлах репозиторію, звітах і чаті.
- Хости стенду — тільки за шаблоном `stands.host_pattern` з `pipeline.config.json`. Продакшн (avto.pro, avtopro.*) — не відкривати.
- Логін на стенді — тільки тестовими користувачами (`StaticUserHelper.TestUsers`): під іншими акаунтами працюють бойові контури Stripe і Recalvi. Реальні платіжні дані — ніколи.
- Azure DevOps — **тільки читання**: не створювати і не змінювати задачі, коментарі, звʼязки, поля (заборонено в `.claude/settings.json`). Баги і коментарі публікує людина.
- Код AvtoPro, CodeWiki і автотести — **тільки читання**, без git-команд, що пишуть (`checkout`, `merge`, `fetch`, `commit`, `stash`, `reset`). Єдиний виняток — `qa-autotests-update`: окремий worktree і гілка `autotests/<ID>` у проєкті автотестів; push і PR — людина.
- Капча, 429 / 423 (антипарсинг), перехід на хост поза стендом — зупинка прогону.

## Стан задачі — у файлах

- Після кожного кроку — рядок у `tasks/<ID>/pipeline.md` (журнал, «де зупинились»).
- Відновлення після перерви — повторний запуск тієї ж команди: вона продовжує з першого незавершеного кроку.
- Знайдене корисне для інших задач (дані, назви в UI, рецепти) — блок «Зберегти в контекст?» (`qa-context-update`); запис — тільки з підтвердження людини і тільки в `context-outbox/`, у CodeWiki переносить людина (`docs/codewiki-qa-section.md`). Dev-режим лише дописує кандидатів у `tasks/<ID>/context-candidates.md`.
