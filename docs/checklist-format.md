# Формат чек-листа — контракт між аналізом PBI і pipeline

Pipeline не аналізує задачу — він довіряє чек-листу. Тому чек-лист, вкладений у PBI, має відповідати цьому формату. Відхилення `qa-checklist-import` показує як «Попередження імпорту».

## Файл

- `.xlsx`, вкладення PBI в Azure DevOps. Кілька версій — береться найновіша з номером задачі або «чек-лист» / «check» у назві.
- Лист **«Check-list»** — перевірки; лист **«Анализ PBI»** — питання і мета (необовʼязковий).

## Лист «Check-list»

Колонки шукаються за заголовком першого рядка, порядок не важливий (назви — `pipeline.config.json` → `checklist.columns`):

| Колонка | Обовʼязково | Що |
| --- | --- | --- |
| `ID` | так | `CHK-001`…, унікальні |
| `Проверка` | так | Що зробити. `[Регресс]` на початку — регресійна перевірка |
| `Ожидаемый результат` | так | Одне перевірюване твердження: текст, значення, стан, ціна |
| `Примечание` | так | Позначки через « · » (нижче) |
| `Прогон 1`, `Прогон 2`, … | так | Результати; список «Успешно, Баг, Пропущено». Pipeline пише в першу вільну колонку копії файла |

Праворуч у вільних колонках можна тримати пари «Ключ:» → значення (`Автор:`, `PBI:`) — вони потрапляють у шапку `checklist.md`.

## Позначки в «Примечание»

Порядок довільний, розділювач — « · » (пробіл, крапка посередині, пробіл).

| Позначка | Обовʼязково | Приклад | Як використовується |
| --- | --- | --- | --- |
| Пріоритет | **так, у кожному рядку** | `P1` / `P2` / `P3` | Порядок прогону; dev-режим бере P1 і P2, P3 (граничні випадки) — тільки QA-режим. Рядок без пріоритету в dev-режим не потрапляє |
| `Только тест-среда` | ні | | Перевірка можлива тільки на тестовому стенді |
| `Данные:` | так | `Данные: ES/PT, гость; продавец с Genei; IP PT` | Основа для зіставлення з довідником TD |
| `Источник:` | так | `Источник: RegressionList FE, стр. 1` | Посилання на джерело очікуваного — йде в баг-репорт |
| `Предусловие:` | ні | `Предусловие: QA заранее сопоставил тарифы.` | Передумова; «QA заранее…» — рядок не йде в dev-режим |
| `Пока считаем:` | ні | `Пока считаем: Q-01` | Допущення до відповіді на питання; dev-режим такі рядки не бере, QA-режим — вердикт «потребує рішення QA» |

Що означають P1 / P2 / P3:

- **P1** — основний сценарій задачі (критерії приймання, головні вимоги PBI); без нього задача не готова.
- **P2** — важливі варіанти і правила: інші ролі, площадки, валідації основних полів.
- **P3** — граничні значення, рідкісні стани, негативні сценарії «на всяк випадок».

## Лист «Анализ PBI»

Колонки A–C: «Анализ PBI» (`Q-01. <опис>`), «Вопрос на уточнение», «Тип вопроса». Тип «Служебное» — службові позначки (наприклад, джерело не прочитано). Праворуч — пари «Региональная версия:», «Тип PBI:» — «Тип PBI» використовується для вибору маршруту S / M / L.

## Чого pipeline не робить з чек-листом

- Не змінює формулювань і не додає перевірок. Знайдена прогалина — «Помічено поза чек-листом» у звіті прогону.
- Не пише в оригінал: результати — у копію `tasks/<ID>/runs/<прогін>/checklist-<прогін>.xlsx`, яку QA прикріплює до PBI сам.
